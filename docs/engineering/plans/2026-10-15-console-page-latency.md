# Console 页面性能修复计划

目标：修复全部已确认读取瓶颈，保持数据、权限、失败与状态语义。基线 8596646；仅隔离工作区交付。

1. 运维：真实只读 SQLite 快照供 Console/CLI 共享，单次读任务/工作流；运行现场每 Pane 最多一次、有界并发，不执行 schema 初始化。保留 superseded/required task 异常与 CLI 输出契约。测试冷进程禁止 DDL/schema lock、归属、去重和并发上限。
2. 白盒/归档：单工作流快照与单任务读取；workflow projection 复用任务对象、有界现场采集；归档在 SQLite 参数化筛选/计数/分页，匹配既有内存实现的搜索、排序、空值规则。测试真实数据库、拒绝全量 inventory、精确兼容。
3. 页面编排：每类刷新一个在途请求，后续 scope 只保留最新一个，旧响应不覆盖当前；overview/project 与页面所需最少数据解耦；经验中心避免重复加载。Node 执行真实 JS，悬挂请求验证去重与反序回包。
4. 日志/成果/项目：日志尾部有界读取；成果定位实际慢点并消除无关 Git/目录扫描，保留任务来源与错误；project 列表拆分必要元数据与现场。测试读取量/超长行/编码/文件变更、成果真实 Git 链。
5. 集成与验收：清理冗余路径，运行全部专项及全量；临时端口预览验证所有受影响页面。更新 Wiki/教训，独立代码评审；报告已修/未部署及准确证据。

不采用增加 TTL 缓存或只缩短超时：会掩盖数据新鲜度与失败，不消除重复工作。
