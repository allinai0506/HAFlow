# Recovery autonomy V1 implementation plan

Goal: close two technical recovery stalls within finite persisted budgets, using existing task and acceptance evidence.
Architecture: existing recovery row detail_json owns budgets/cursors. Controller classifies only a read-only Git preflight timeout as safely retryable; an effect barrier forces receipt-only verification after interruption. Checkpoint integrity is checked outside the write transaction; same-snapshot versions and episode are checked before consumption.
Tech stack: Python standard library, SQLite, pytest.
Route: FRESH / bug / medium / state_machine+concurrency+data_integrity / database; unified spec = user acceptance matrix plus this plan; controller=none (root owns sequential execution); red_first; adversarial; delivery=Draft PR.

## Constraints and alternatives
No production mutation, restart or real Agent. No templates, routing, wrapup strategy or test-command changes. Do not enlarge an absolute deadline alone, infer safety from started=0, or reset legacy budgets. No separate state source.
Existing idle interval 3600s and attempt cap 3 remain. New pinned total defaults to three idle windows (10800s), a finite engineering policy, not a supplied SLA. Config recovery_budget permits idle 60..3600 and total idle..86400; retry delay 30/60s and maximum three execution attempts reuse existing cap/poll cadence. Unknown effects verified for at most 600s and within total. Configuration validation precedes effects; later edits never replenish existing budgets.

## Independent review round 1 corrections

Three independent read-only reviewers (Standards, Spec, and interrogate cross-model) returned NEEDS_FIXES. Six findings were accepted; seven RED cases reproduced all of them before repair. Fresh regressions additionally cover byte-limited backlog and mutation between preparation and the writer.

- Chronological source-filtered checkpoint scanning persists per-scope scan cursors. A 64-record/8 MiB batch cannot turn an unexamined backlog into no-progress; a later tick resumes the same scan, still clipped by total deadline. Invalid/duplicate records advance scanning only, never idle time.
- Existing owner renewal/effect validation now stops further effects once total budget expires; confirmed receipt bookkeeping remains allowed. Expired leases also retain the specific total-budget reason.
- Successor maps persist the confirmed delivery epoch/path, and progress revalidates them. Consumption is scoped to Task/Run across epoch rejudgment so repeated content/phases remain consumed.
- Same-key fact refresh never reactivates a pre-existing waiting_human, including empty detail; manual verify never invents missing historical time.
- Artifact inode/device/size/mtime_ns/ctime_ns are sampled before hashing, checked after hashing and again during the short writer CAS. These are stability checks on a verified digest, not independent progress proof. No content hashing runs under BEGIN IMMEDIATE.

Read-only closure from already-valid full acceptance after a delayed poll remains allowed: it ends the obligation and initiates no new effects or idle extension. It is distinct from authorizing execution past the total budget.
