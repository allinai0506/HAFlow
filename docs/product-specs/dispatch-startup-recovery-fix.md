# 首节点派发失败恢复与空交付防护

## 规格
首次节点尚无 candidate_sha 是合法状态。已发出的派发失败且没有注册 Task 时，经现有现场核查和明确未执行确认，可以原子废弃旧授权并建立新派发；依赖节点仍要求冻结候选。未知启动现场、运行身份缺失、旧代未结案、重复恢复必须拒绝。
配置了节点的工作流不能在零 Task 时声称 delivered；显式 abandon 应记录 abandoned。拒绝必须发生在任何关闭副作用之前。
Agent 就绪失败不得假装成功，不通过改超时或跳过启动检查掩盖。底层启动交互尚未确认，保持现有安全回滚。

## 计划与任务
1. 建立真实 SQLite 恢复及 CLI 关闭失败回归。
2. 修正首节点恢复身份条件；保留候选、Run、版本及现场检查。
3. 修正空任务关闭入口和 abandon outcome。
4. 验证旧凭证拒绝、重复恢复拒绝和未知现场防重派。
5. 清理、全量回归、独立评审及 Wiki/教训同步。

## 非目标
本次交付仅本地代码；不重启、不部署、不修改已有工作流状态、不自动启动真实 Agent。
