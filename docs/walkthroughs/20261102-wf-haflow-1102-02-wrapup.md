## 六、交付 PR 与合并指引

1. 交付 PR 由平台 `herdr-task create-pr` 在候选专属分支创建；PR URL、base、head 以
   `create-pr` 输出与 `pull_request_created` 事件为准（认证后补全）。
2. 合并前必须完成 §四 审核闭环：CI 全绿、未决 P1=0、P2/P3 逐条处置。
3. 本工作流不自动合并、不部署；合并需作者/评审另行授权。
4. 合并后如需执行 six-step-finish 步骤 3–6（合并确认、锚点同步、分支核对、卫生检查），
   应另起已授权收尾；不得在本工位自动删除 clone/pane/阶段 tab（`close-workflow` 职责）。
5. 禁止 rebase 交付分支：会使 PR head 偏离已认证候选，导致回执失效；如需同步 main 使用
   merge commit 并重新验证。
